# ワークスペース・プロジェクト・メンバーの設定と event bus（#133）凍結テスト対応表

凍結点: `origin/python-host` / `fea9e05aaf8b4bca96e19d615b6811ea0eacb7d0`。
対象は 19 ファイル・331 テスト関数（パラメータ展開前）。各関数を個別の行にし、移した先の
Rust のテストに確かめる条件を添える。同じ Rust テストへ集めた行も省略しない。

## 境界と条件の差

- 比較（compare-and-set）は凍結版と同じく、送られた revision のキーだけを比べ、送られていない
  パスは比べない（`""` は「無いこと」）。identity のファイルも拒否の `path` は `config/<相対パス>`、
  `revisions` は送られたキーの今の値。範囲外のキーは 400 `config_revision_invalid`。
- 書き込みの応答は `{"revisions": ...}` だけを返す。凍結版の `project` / `member` /
  `intelligence` の `files` の一覧は画面が読まないので移さない（desktop の型からも外す）。
- 設定ファイルは JSON（YAML でもある）で書き、凍結版の `save_yaml_file` と同じく null と空文字の
  キーを省く。ファイルの bytes（と revision）は Python 版と一致しない。
- Branvil と Slack の service と member の model・hook・avatar の取込は #91。それまでの registry は
  provider の項目をそのまま保存し（名前は小文字）、member のアカウントの form は受けない。
- メンバーの保存は、form が送ったアカウントの provider の `account_info` のキーだけを置き換え、ほかの
  provider の保存済みのキーは残す（凍結版は全 provider のアカウントの form から作り直す。#91 までの
  registry はアカウントの model を持たず、画面が送り返せないため）。
- 読み取りに合わせて組み立てた保存（`expected_revisions` を送る PUT /config/project・POST
  /config/members・PUT /config/members/{id}）は、読んだ `config_dir` を必ず送り、選択中の
  ワークスペースの config を名指さないものは 409 `config_changed`（`path` は `config`）で断る。
  revision は 2 つのワークスペースのファイルを中身でしか区別しないため（凍結版の project は送られた
  `config_dir` へ書き、member は送られたものを無視して選択中へ書く）。GET /config/members/{id} は
  project と同じく読んだ `config_dir` を返し、画面のメンバーの保存はそれを送る（凍結版のメンバーの読み取りは
  返さない。golden の比較はこのフィールドを外す）。画面は、読んだスナップショットの
  ワークスペースが変わったプロジェクトのフォームと、サーバーが別のワークスペースを開いたあとの
  メンバーの画面を作り直すので、あるワークスペースで入力したものを別のものの保存先と送らない。
- ワークスペースの切り替えとサービスの開始は、HTTP の要求ではなくサーバーの作業（`api.work`）として
  最後まで走り、停止するサーバーはそれを待つ（凍結版の要求も、クライアントが切断しても取り消され
  ない）。待ったあとに選択中のサービスを取り消して止め（停止を頼まれたあとに始まったもの）、最後の
  選択の system transcript を閉じる。
  登録の取り消しは、進行中の切り替えが終わるのを待ってから選択中かを確かめる。
- GitHub provider は #88 で削除済み。GitHub を素材にした行は provider に依らない性質だけを、
  テスト用の provider（gb-setup）か本物の registry（gb-server）で確かめる。
- `/config/init` の `config_dir` は `<workspace>/.guildbotics/config` の形だけを受ける（凍結版の
  任意の config ディレクトリは無い）。
- ワークスペースの切り替えは、サービスとコマンドの作業が無いときだけ受け、member backend・
  サービス・診断の記録先を新しいワークスペースで作り直す。プロセスの環境変数と cwd は変えない
  （Rust のサーバーは `.env` も Secret の環境変数への読み込みも持たない）。
- `tracing` のログを診断の記録へ流す橋（凍結版の `EventBusLogHandler`）は #134。bus は
  `publish_log` で記録だけをする。
- 読み取り（/team・/config/members・/identities）は鍵を取らず、revision を読んだバイトそのものから取る。
  /config/project の API キーの有無は secret store を読むので、store の索引と暗号文を一緒に読む鍵を取り、
  他者が鍵を持つ間は保存と同じく 503 `config_busy` を返す（凍結版は鍵を取らずに読む）。
- 新しい project の保存は、secret store の鍵を先に書き、project のファイルをあとに書く（凍結版は逆）。
  store が使えないときに、持っていない鍵を名指す project を残さないため。
- ワークスペースの切り替えは、コマンド・member の実行・サービスの開始を受け付けている間（`Api::admit`）は
  409 で断る。凍結版は 2 つ目の切り替えを待たせるが、Rust はこれも 409 にする。
- avatar の保存は選択中のワークスペースを要る（凍結版は identity だけで書けた）。画面は選択中の
  ワークスペースのメンバー画面からしか保存しない。
- 実行記録の保存期間での削除（凍結版の `start_maintenance`）は、Rust のサーバーにまだ無い。診断（#134）で移す。
- Branvil を起動する Rust のテスト（gb-integrations、gb-member）はプロセスに 1 つの Git の lock を
  持つので、CI と同じく nextest（テストごとのプロセス）で流す。
